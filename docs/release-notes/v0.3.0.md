# Logcove CLI and Skills v0.3.0

Manage your log sources, download Parquet to your own computer, and explore logs with your preferred coding agent. This release aligns the CLI and bundled Skill with the current Logcove API.

## September 19 rebuild

This v0.3.0 replaces the original v0.3.0 binaries and Skill assets. It adds personal
access tokens for CI and remote agents through `LOGCOVE_TOKEN`, without requiring
an OS credential store. Invalid tokens never fall back to a saved account, and
token mode leaves existing browser-login credentials untouched.

The version number remains 0.3.0. Download the replacement archive and verify its
new SHA256SUMS; `logcove --help` must mention `LOGCOVE_TOKEN`. Reinstall the bundled
Skill with `--force` after reviewing local customizations. Merely checking
`--version` cannot distinguish the two builds.

Personal tokens require a compatible API/app deployment. This release does not
deploy the production service or enable its Personal tokens page; continue using
browser login until token support is available in your environment. Tokens grant
Full access to business resources, but cannot manage billing, account security or
other personal tokens. Collector write keys remain separate.

## Highlights

- **Sign in directly.** Run `logcove login` without configuring an API address. Existing development and self-hosted overrides remain in effect.
- **Manage Projects and write keys.** Create, update, archive and restore Projects. Choose HTTP JSON or OTLP/HTTP ingestion when creating a Project. Create and manage write keys; a new key's secret is written only to the private file specified by `--output`, while the command returns its path and masked metadata.
- **Reuse downloaded logs.** Pass one or more `--reuse-manifest` paths to `logcove data pull`. The CLI refreshes the authorized file list, copies matching cached files into a new complete snapshot and downloads only missing or changed files. Downloads run with a default concurrency of four.
- **Save portable Chart definitions.** Store SQL, Vega-Lite specs and the complete Project dependency list. Compute results locally with DuckDB or in the Logcove application.
- **Updated agent Skill.** Includes Project/Key management, JSON and OTLP ingestion guidance, local cache reuse, time-filtered analysis, and single-SELECT validation for saved Charts.
- **Clearer failures.** Project quota limits, Chart revision conflicts, and Key binding or revocation failures retain their business error codes. Chart text limits now match the API for Unicode input.

## Upgrade from v0.1.x or v0.2.x

This release changes the Chart contract:

- `--result-file` and `logcove charts result put` have been removed. The API stores definitions only; do not upload calculated result rows.
- When creating a Chart, declare every SQL source with repeated `--project-id`. SQL updates must provide the complete source list, or `--clear-projects` for a query without Project sources.
- Save a single SELECT query, including WITH/CTEs, against Project views. The application filters those views by `_created_time` for the selected time range. Keep setup statements and current time-window values outside saved SQL.
- Known HTTP 409 errors can now return `PROJECT_LIMIT_REACHED`, `CHART_CONFLICT`, `WRITE_KEY_CONFLICT`, `INVALID_KEY_BINDING`, or `KEY_REVOKED`; scripts that previously matched only `CONFLICT` should handle these codes.

Replace your installed binary, then update the Skill for the agent you use. Review any local Skill customizations before using `--force`:

```sh
logcove --version
logcove skills install --agent codex --force
# For Claude Code, use --agent claude instead.
```

If `LOGCOVE_TOKEN` is set, verify CLI support with `logcove --help`, then run
`logcove whoami`. Otherwise use `logcove login` for browser authorization.

Existing configuration and origin-scoped login credentials are preserved. No account migration is required.

## Downloads and limitations

Release assets include macOS ARM64/x64, Linux ARM64/x64 and Windows x64 binaries, the matching standalone Skill ZIP, Homebrew/WinGet metadata, and SHA256SUMS. Use the installation guide in the release's README.

- Homebrew and WinGet metadata is included, but public package-manager installation is not enabled yet.
- Packages are unsigned and not notarized. Linux browser login requires an unlocked Secret Service; personal-token mode does not.
- DuckDB and any chart renderer are installed separately; the CLI does not execute SQL or export chart images.
- Local cache reuse copies files into each new snapshot. It saves network downloads but still consumes local disk space.
- OTLP support is for HTTP Protobuf Logs. Application shutdown follows the chosen SDK's lifecycle and does not guarantee delivery after timeouts, export failures, or forced termination.
