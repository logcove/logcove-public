# Logcove CLI and Skills v0.3.1

This patch exposes Project raw-log usage in CLI output and updates the bundled
Skill for the Logcove online service.

## Changes

- Project list, get and management responses preserve the API's read-only
  `usage` metadata. `raw_bytes` measures normalized, uncompressed log writes
  over the latest 90 UTC calendar dates; dates, tracking start and last report
  time are included. Download sizes still refer to actual Parquet bytes.
- The Skill uses the production API and web URLs. It includes no development
  environment setup or deployment instructions.
- Ingestion guidance lists the HTTP JSON and OTLP/HTTP Protobuf Logs endpoints
  and Project/write-key headers. It leaves OpenTelemetry SDK, instrumentation
  and application lifecycle choices to the user.
- Installation guides point to v0.3.1. CLI archives now include `INSTALL.md` for
  installation through your coding agent.

## Upgrade

Download the package for your platform from this release, verify it against
`SHA256SUMS`, and replace your installed binary. Existing login credentials,
configuration and completed download manifests remain usable.

Update the bundled Skill for the agent you use. Review local customizations
before replacing an older copy:

```sh
logcove --version
logcove skills install --agent codex --force
# For Claude Code, use --agent claude instead.
```

The version command should print `logcove 0.3.1`. Install the complete matching
Skill; upgrading the CLI does not automatically update an installed Skill.

## Downloads

Assets include macOS ARM64/x64, Linux ARM64/x64 and Windows x64 binaries, the
standalone Skill ZIP, Homebrew/WinGet metadata, and `SHA256SUMS`.

Homebrew and WinGet publication remains pending. Packages are unsigned and not
notarized. Linux binaries require GNU/glibc; ARM64 uses the Ubuntu 24.04/glibc
2.39 baseline. Windows requires the x64 Microsoft Visual C++ Runtime. Linux
browser login needs an unlocked Secret Service; personal-token authentication
through `LOGCOVE_TOKEN` does not.

DuckDB and chart renderers remain separate installations. The CLI downloads
data and manages definitions; it does not execute SQL or export chart images.
