# Logcove CLI and Skills v0.3.2

This patch makes log downloads tolerate files changing during compaction and
updates the Skill to analyze a consistent set of downloaded logs.

## Changes

- `data pull` refreshes the entire file listing once after `FILE_SET_CHANGED`,
  `FILE_UNAVAILABLE`, or a storage download returning HTTP 404. It starts again
  from the first page and reuses completed downloads only when the current key,
  ETag, size and local file validation match.
- Each attempt has its own directory. Only a successful complete pull publishes
  a manifest; a second file-refresh failure is returned without further retries.
  Permission failures and missing Projects do not trigger this retry.
- The Skill uses only the newly returned manifest after refreshing a dataset.
  Compaction can give the same logs different file names: combining overlapping
  old and new snapshots would count those logs twice. Separate pulls may be
  combined only for non-overlapping UTC ingestion-date coverage.

## Upgrade

Download your platform's package, verify it against `SHA256SUMS`, and replace
your installed binary. Existing login credentials, configuration and completed
download manifests remain usable. Older CLIs can still read the service, but
may need a manual rerun when files change during a download.

Reinstall the matching Skill after reviewing any local customizations:

```sh
logcove --version
logcove skills install --agent codex --force
# For Claude Code, use --agent claude instead.
```

The version command should print `logcove 0.3.2`. Updating the binary does not
automatically update an installed Skill.

## Downloads and limitations

This release includes macOS ARM64/x64, Linux ARM64/x64 and Windows x64 binaries,
the standalone Skill ZIP, Homebrew/WinGet metadata, and `SHA256SUMS`.

Homebrew and WinGet publication remains pending. Packages are unsigned and not
notarized. Linux binaries require GNU/glibc; ARM64 uses the Ubuntu 24.04/glibc
2.39 baseline. Windows requires the x64 Microsoft Visual C++ Runtime. Linux
browser login needs an unlocked Secret Service; personal-token authentication
through `LOGCOVE_TOKEN` does not. DuckDB and chart renderers remain separate
installations.
